<Status state="planned" />

```bash
bimai new a2-knooppunt
```

This creates the shared project on your company's git host, puts it in `bimai/projects/`, and starts
the onboarding interview.

## The interview

About three minutes. In Claude Code, the questions appear as clickable choices with a short explanation, the best fit marked *Recommended*, and an *Other* field for your own words; bimai suggests answers from what it finds in your folder. (Filling answers in from the BEP comes with BEP reading.)

1. **Your role on this project.** For example design coordinator, BIM coordinator or BIM modeller.
2. **The BIM execution plan.** Drop the Word or PDF file. bimai reads it and fills in most of the
   remaining questions. See [Your BEP becomes the rules](/docs/guides/bep).
3. **The project goal and phase.**
4. **What you want help with.** Requirements, risks, planning, reporting, issues, model checks,
   deliveries, meetings.
5. **Which tools and data are used.** Software and versions, the CDE, Relatics, the planning.
   bimai connects your team to the tools it can reach on this computer. When a tool needs the bimai
   bridge (Civil 3D), Claude asks whether to install it now. A tool that only runs on Windows says
   *Windows only* on a Mac: you can still pick it, and your team connects to it on a Windows PC.
6. **How familiar you are with VS Code.** If not, a Mentor joins your team to help.
7. **Output language.** Dutch or English.

bimai then proposes your team, for example:

```
Proposed team (4 of max 5):
🧭 Coordinator                    always
📐 Requirements & Risk Manager    goals: requirements, risks · data: Relatics
📅 Planning Analyst               goal: planning · data: Primavera XML
✍️  Scribe                         goal: progress reporting
```

As the first person you also confirm the **rule owners**: the people who approve changes to the
project's shared rules (for example the information manager).

## Invite colleagues

```bash
bimai invite anna@company.nl
```

If you're allowed to give access on the git host, bimai does it. Otherwise it tells you what to ask
IT. Colleagues then [join the project](/docs/start/join).

## Already have a project folder?

<Status state="available">`bimai init` works today, for one person per project. Reading the BEP and inviting colleagues come later.</Status>

Run `bimai init` in the folder where your project lives, new or existing. bimai looks at what's
already there, asks a few questions, and proposes your team.

```bash
curl -LsSf https://docs.bimai.nl/install.sh | sh   # Windows: powershell -ExecutionPolicy ByPass -c "irm https://docs.bimai.nl/install.ps1 | iex"
cd ~/projects/knooppunt
bimai init
```

What it looks for: models (IFC, Revit, Navisworks, DGN, DWG), BCF issues, IDS files, the BEP or EIR
(by file name), Primavera and MS Project planning exports, Relatics exports and meeting transcripts.
It only reads file names, and the first line of XML files; it changes nothing.

After you confirm, it writes:

| File | What |
|---|---|
| `.bimai/` | The project, you, your position and your seat with your team |
| `.claude/agents/` | One file per team member, each on its own model tier (see [costs](/docs/why/costs)) |
| `CLAUDE.md` | The Coordinator's instructions, in a marked block. Your own text in this file is kept |
| `.claude/settings.json` | The main session on sonnet, unless you already chose a model |
| `.gitignore` | Keeps machine files and raw data exports out of git |

It never overwrites a file you already have. Then open Claude Code in the folder (`claude`) and your
team is there.

**Useful options:** `--dry-run` shows everything without writing. `--role`, `--goals`, `--tools`,
`--language` and `--yes` answer the questions up front, so Claude Code or a script can run it for
you:

```bash
bimai init --role "BIM coordinator" --goals issues,meetings --tools acc --yes
```
