---
title: Running a pilot
description: A six-week plan to try bimai with one project team.
---

<Status state="planned" />

A pilot works best on one running project with a small, willing team: for example a BIM coordinator,
one or two modellers and a design coordinator.

<Steps>
<Step>

### Week 0: prepare

- Pick the project and the people.
- Arrange a Claude account and a git host (GitHub or Azure DevOps) through IT.
- Where relevant, inform the works council about the session journal.

</Step>
<Step>

### Week 1: set up and try the demo

- Everyone runs `bimai setup` and tries the demo project (no accounts needed).
- The BIM coordinator starts the project with the BEP; the others join.

</Step>
<Step>

### Weeks 2–3: read-only work

- Process coordination meeting transcripts into minutes and tasks.
- Daily issue digest and weekly design progress report.
- Nothing is written to models or ACC yet.

</Step>
<Step>

### Weeks 4–5: approved changes

- Switch the project to approved writes: agents propose, people approve.
- Try covering for an absent colleague and a handover.

</Step>
<Step>

### Week 6: evaluate

- Hours saved on minutes, reports and triage (by the team's own estimate).
- Quality: were the minutes right, were the right people asked?
- Adoption: who used it, and what stopped others?

</Step>
</Steps>
